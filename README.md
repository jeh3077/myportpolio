## 🗓️ Day 1: 컴퓨터 구조 & 데이터

### 📌 Chapter 1. 컴퓨터 구조
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 컴퓨터가 이해하는 정보
* **데이터:** 숫자, 문자, 이미지 등 정적인 정보
* **명령어:** 데이터를 움직이고 작동시키는 정보 (ex. 1과 2를 출력하라. 데이터 : 1, 2 / 명령어 : 출력하라)

#### 2. 핵심 부품 4가지
1.  **CPU:** 산술논리연산장치, 제어장치, 레지스터로 구성 (컴퓨터의 두뇌)
2.  **메모리:** 실행 중인 프로그램의 명령어와 데이터 저장
3.  **보조기억장치:** 전원이 꺼져도 저장 (HDD, SSD)
4.  **입출력장치:** 마이크, 스피커, 키보드 등

#### 3. 확인문제
1.  컴퓨터가 이해하는 정보에는 데이터와 명령어가 있습니다.
2.  명령어를 해석하고 실행하는 장치 -> **CPU**
3.  프로그램이 실행되려면 반드시 **메모리**에 저장되어 있어야 합니다.
4.  **보조기억장치** : 보관할 프로그램 저장 / **메모리** : 실행되는 프로그램 저장
5.  시스템 버스에 관련한 내용
</details>

### 📌 Charter 2. 데이터
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 0과 1로 숫자를 표현하는 방법 : 이진법
* 0과 1을 나타내는 가장 작은 정보 단위를 **비트(bit)**라고 한다.
* **ex) 2비트로 표현할 수 있는 정보:** 00 / 01 / 10 / 11 (따라서 n개의 비트로 표현할 수 있는 상태는 $2^n$가지)
* **단위:** 프로그램의 크기를 말할 때는 비트보다 큰 단위인 **바이트(byte)**를 사용한다. (1 byte = 8 bit, $2^8$ 개의 정보를 표현)
* **음수 표현:** 0과 1로 음수를 표현하기 위해 **2의 보수**를 사용한다.

#### 1-2 확인문제
1) 2000MB -> **2GB** 2) 1000GB = **TB** / 1000kB = **1MB** / 1000MB = **1GB** / 1024 bit  

#### 2. 0과 1로 문자를 표현하는 방법
* **문자 집합:** 컴퓨터가 이해할 수 있는 문자의 모음
* **인코딩:** 문자를 0과 1로 이루어진 문자코드로 변환하는 과정
* **디코딩:** 0과 1로 표현된 문자 코드를 문자로 변환하는 과정
* **아스키 코드:** 7비트로 하나의 문자 표현 (총 8비트 중 1비트는 패리티 비트)
* **EUC-KR:** 한글 완성형 인코딩 방식 (모든 한글 표현은 불가)
* **유니코드:** 통일된 문자 집합 (한글, 영어, 특수문자, 이모티콘 포함)
* **인코딩 방식:** utf-8, utf-16 등

#### 2-1. 확인문제
1.  hongong
2.  **EUC-KR 설명:** 한국어 인코딩 방식 / 완성형 / 한글 글자에 코드를 직접 부여 / 모든 한글 표현 불가
3.  **'안녕'의 유니코드 변환:**
    * **안** => C548 => 11101100 10010101 10001000
    * **녕** => B155 => 11101011 10000101 10010101
    * **답:** 1110 1100 1001 0101 1000 1000 1110 1011 1000 0101 1001 0101 (2)
</details>

### 📌 Charter 3. 명령어
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 소스 코드와 명령어
* **고급 언어:** 사람을 위한 언어
* **저급 언어:** 기계어, 어셈블리어
* **컴파일 언어:** 컴파일러를 통해 소스 코드 전체가 저급 언어로 변환되어 실행 (C 등)
* **인터프리터 언어:** 소스 코드를 한 줄씩 실행 (Python 등)

#### 1-2. 확인문제
1) 고급 언어가 아닌 것: **기계어, 어셈블리어** 2) 옳고 그름 판단:
    * 컴파일 언어는 오류 발생 시 실행 불가 (O)
    * 일반적으로 컴파일 언어가 인터프리터 언어보다 빠르다. (O)
    * 인터프리터는 한 줄씩 실행한다. (O)

#### 2. 명령어의 구조
* **연산 코드:** 명령어가 수행할 연산 (MOVE, STORE, LOAD, PUSH, POP 등)
* **오퍼랜드:** 연산에 사용할 데이터 또는 데이터의 위치(주소)
* **주소 지정 방식:** 유효 주소(실제 데이터 위치)를 찾는 방법
    1.  **즉시 주소:** 데이터를 오퍼랜드 필드에 직접 명시
    2.  **직접 주소:** 유효 주소를 오퍼랜드 필드에 직접 명시
    3.  **간접 주소:** 유효 주소의 주소를 명시 (가장 느림)
    4.  **레지스터 주소:** 데이터가 저장된 레지스터를 명시
    5.  **레지스터 간접 주소:** 유효 주소를 저장한 레지스터를 명시

#### 2-1. 확인 문제
1) 연산 코드 필드에는 주소만 담을 수 있다 (**X** - 수행할 연산이 담김)  
2) 레지스터 간접 주소 지정 방식 수행 결과: (1) **6** (2) **200**
</details>

## 🗓️ Day 2: CPU의 작동 원리

### 📌 Charter 4. CPU의 작동 원리
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. ALU와 제어장치
* **ALU:** 레지스터에서 피연산자를, 제어장치에서 제어 신호를 받아 연산 수행. 결과값과 함께 **플래그**를 출력.
* **제어장치:** 클럭, 명령어, 플래그, 제어 신호를 바탕으로 내/외부 제어 신호 발생.

#### 2. 레지스터 (핵심 종류)
* **프로그램 카운터(PC):** 메모리에서 가져올 명령어의 주소 저장
* **명령어 레지스터(IR):** 메모리에서 읽어 들인 명령어를 저장
* **메모리 주소 레지스터(MAR):** 메모리의 주소 저장
* **메모리 버퍼 레지스터(MBR):** 메모리와 주고받을 데이터/명령어 저장
* **플래그 레지스터:** 연산 결과 및 CPU 상태 정보 저장
* **범용 레지스터:** 데이터와 주소 모두 자유롭게 저장
* **스택 포인터:** 스택 최상단의 위치 저장

#### 3. 확인 문제
* **레지스터 매칭:** PC-가져올 주소, IR-해석할 명령어, MAR-메모리 주소, MBR-데이터 저장 등.
* **연산 결과 해석:** 플래그 100000(부호 비트 1=음수), 결과값 101(2)일 때 십진수 값은? -> **답: -3**
</details>

### 📌 Charter 5. CPU 성능 향상 기법
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 클럭, 코어, 스레드
* **클럭:** 속도 단위(Hz). 높을수록 빠르나 발열 한계 존재.
* **코어:** CPU 내부에서 명령어를 실행하는 실제 부품.
* **스레드:** 하나의 코어가 동시에 처리하는 작업 단위.

#### 2. 명령어 파이프라인
* **파이프라이닝:** 인출-해석-실행-저장 단계를 겹쳐 실행하여 효율 극대화.
* **위험:** 데이터 위험(의존성), 제어 위험(분기), 구조적 위험(자원 충돌).
* **비순차적 명령어 처리(OoOE):** 데이터 의존성이 없는 명령어를 먼저 처리하여 중단 방지.

#### 3. CISC vs RISC
* **CISC:** 복잡하고 다양한 가변 길이 명령어. 주소 지정 방식이 다양함.
* **RISC:** 단순하고 적은 수의 고정 길이 명령어. 1클럭 내외 수행, 파이프라이닝 최적화.
</details>

## 🗓️ Day 3: 메모리와 저장장치

### 📌 Charter 6. 메모리와 캐시 메모리
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. RAM의 특징과 종류
* **DRAM:** 데이터가 점차 사라짐, 주기적인 재활성화 필요. (주기억장치용)
* **SRAM:** 데이터 유지됨, 빠름. (캐시 메모리용)
* **DDR SDRAM:** 대역폭을 넓혀 속도를 비약적으로 높인 방식.

#### 2. 메모리의 주소 공간
* **물리 주소:** 하드웨어 실제 주소.
* **논리 주소:** 실행 중인 프로그램이 사용하는 주소.
* **MMU:** 논리 주소를 물리 주소로 변환하는 장치.
* **한계 레지스터:** 프로그램의 논리 주소 범위를 제한하여 메모리 보호.

#### 3. 캐시 메모리
* **계층 구조:** L1 - L2 - L3 (CPU에 가까울수록 빠르고 비쌈)
* **참조 지역성:** 시간 지역성(최근 사용), 공간 지역성(근처 사용) 원리로 데이터 예측.
</details>

### 📌 Charter 7. 보조기억장치
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. HDD와 플래시 메모리
* **HDD:** 플래터, 스핀들, 헤드 사용. 탐색 시간/회전 지연 발생.
* **플래시 메모리:** 셀 단위 저장 (SLC, MLC, TLC).
    * 읽기/쓰기 단위: **Page** / 삭제 단위: **Block**
    * 가비지 컬렉션: 유효하지 않은 데이터를 정리하는 기능.

#### 2. RAID 기술
* **RAID 0:** 스트라이핑 (분산 저장, 속도 향상)
* **RAID 1:** 미러링 (복사본, 안전성 향상)
* **RAID 4/5:** 패리티 비트를 통한 오류 복구 (RAID 5는 패리티 분산 저장)
* **RAID 6:** 두 종류의 패리티 사용 (가장 안전)
</details>

## 🗓️ Day 4: 입출력장치 & 운영체제 기초

### 📌 Charter 8. 입출력장치
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 장치 컨트롤러와 드라이버
* **장치 컨트롤러:** CPU와 장치 간 속도 차이 극복 및 중개 (데이터/상태/제어 레지스터 포함).
* **장치 드라이버:** 장치 컨트롤러를 제어하는 OS 소프트웨어.

#### 2. 입출력 방식
* **프로그램 입출력:** CPU가 직접 레지스터를 읽고 쓰는 방식 (메모리 맵 / 고립형).
* **인터럽트 기반:** 장치가 준비되면 CPU에 알림. (PIC 활용)
* **DMA 입출력:** CPU를 거치지 않고 메모리와 장치가 직접 통신. 시스템 버스 부하를 위해 **입출력 버스**를 별도로 사용.
</details>

### 📌 Charter 9 & 10. 운영체제와 프로세스
<details>
<summary><b>상세 내용 보기 (클릭)</b></summary>

#### 1. 운영체제의 핵심 기능
* **커널:** 운영체제의 심장부, 핵심 서비스 담당.
* **이중 모드:** 사용자 모드(제한됨)와 커널 모드(자원 접근 가능) 구분.
* **시스템 호출:** 사용자 프로그램이 OS 서비스를 받기 위해 커널 모드로 전환하는 요청.

#### 2. 프로세스와 스레드
* **PCB:** 프로세스 정보를 담은 블록 (PID, 레지스터 값, 상태 등 저장).
* **문맥 교환:** 기존 작업을 PCB에 백업하고 새로운 작업을 복구하는 과정.
* **메모리 영역:**
    * **코드 영역:** 기계어 명령어 저장 (정적)
    * **데이터 영역:** 전역 변수 저장 (정적)
    * **힙 영역:** 프로그래머가 직접 할당 (동적, 낮은 주소 -> 높은 주소)
    * **스택 영역:** 지역 변수 등 일시적 저장 (동적, 높은 주소 -> 낮은 주소)

> **핵심 포인트:** 힙과 스택의 방향이 반대인 이유는 한정된 가용 공간을 유연하게 공유하여 메모리 충돌을 방지하기 위해서입니다.
</details>
