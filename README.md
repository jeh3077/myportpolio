## 🗓️ Day 1: 컴퓨터 구조 및 데이터 표현

### 📌 Chapter 1. 컴퓨터 구조
#### 1. 컴퓨터가 이해하는 정보
* **데이터:** 숫자, 문자, 이미지 등 정적인 정보
* **명령어:** 데이터를 움직이고 작동시키는 정보 (ex. 1과 2를 출력하라. 데이터 : 1, 2 / 명령어 : 출력하라)

#### 2. 핵심 부품 4가지
1.  **CPU:** 산술논리연산장치, 제어장치, 레지스터로 구성 (컴퓨터의 두뇌)
2.  **메모리:** 실행 중인 프로그램의 명령어와 데이터 저장
3.  **보조기억장치:** 전원이 꺼져도 저장 (HDD, SSD)
4.  **입출력장치:** 마이크, 스피커, 키보드 등

#### 3. 확인문제
1.  컴퓨터가 이해하는 정보에는 데이터와 명령어가 있습니다.
2.  명령어를 해석하고 실행하는 장치 -> **CPU**
3.  프로그램이 실행되려면 반드시 **메모리**에 저장되어 있어야 합니다.
4.  **보조기억장치** : 보관할 프로그램 저장 / **메모리** : 실행되는 프로그램 저장
5.  시스템 버스에 관련한 내용

### 📌 Charter 2. 데이터
#### 1. 0과 1로 숫자를 표현하는 방법 : 이진법
* 0과 1을 나타내는 가장 작은 정보 단위를 **비트(bit)**라고 한다.
* **ex) 2비트로 표현할 수 있는 정보:** 00 / 01 / 10 / 11 (따라서 n개의 비트로 표현할 수 있는 상태는 $2^n$가지)
* 비트는 가장 작은 단위이므로 프로그램의 크기를 말할 때는 비트보다 큰 단위인 **바이트(byte)**를 사용한다.
* **바이트:** 여덟 개의 비트를 묶은 단위. (1 byte = 8 bit, $2^8$ 개의 정보를 표현)
* **음수 표현:** 0과 1로 음수를 표현하기 위해 **2의 보수**를 사용한다.

#### 1-2 확인문제
1) 2000MB -> **2GB** 2) 1000GB = **TB** / 1000kB = **1MB** / 1000MB = **1GB** / 1024 bit

#### 2. 0과 1로 문자를 표현하는 방법
* **문자 집합:** 컴퓨터가 이해할 수 있는 문자의 모음
* **인코딩:** 문자를 0과 1로 이루어진 문자코드로 변환하는 과정
* **디코딩:** 코드를 해석하는 과정, 0과 1로 표현된 문자 코드를 문자로 변환
* **아스키 코드:** 7비트로 하나의 문자 표현 (총 8비트 중 1비트는 오류검출용 패리티 비트)
* **EUC-KR:** 한글 완성형 인코딩 방식 (모든 한글 표현은 불가)
* **유니코드:** 통일된 문자 집합 (한글, 영어, 특수문자, 이모티콘 포함)
* **인코딩 방식:** utf-8, utf-16 등

#### 2-1. 확인문제
1.  hongong
2.  **EUC-KR 설명:** 한국어 인코딩 방식 / 완성형 / 완성된 한글 글자에 코드 부여 / 모든 한글 표현 불가
3.  **'안녕' 변환 과정:**
    * **안** => C548 => 11101100 10010101 10001000
    * **녕** => B155 => 11101011 10000101 10010101
    * **답:** 1110 1100 1001 0101 1000 1000 1110 1011 1000 0101 1001 0101 (2)

### 📌 Charter 3. 명령어
#### 1. 소스 코드와 명령어
* **고급 언어:** 사람을 위한 언어
* **저급 언어:** 기계어, 어셈블리어
* **컴파일 언어:** 컴파일러를 통해 소스 코드 전체가 저급 언어로 변환되어 실행 (C 등)
* **인터프리터 언어:** 소스 코드를 한 줄씩 실행하는 언어 (Python 등)

#### 1-2. 확인문제
1) 고급 언어가 아닌 것: **기계어, 어셈블리어** 2) **컴파일/인터프리터 특징:**
    * 컴파일 언어는 오류 시 실행 불가
    * 일반적으로 컴파일 언어가 인터프리터 언어보다 빠름
    * 인터프리터는 한 줄씩 실행함

#### 2. 명령어의 구조
* **연산 코드:** 명령어가 수행할 연산 (MOVE, STORE, LOAD, PUSH, POP 등)
* **오퍼랜드:** 연산에 사용할 데이터가 저장된 위치
* **주소 지정 방식 (유효 주소를 찾는 방법):**
    1.  **즉시 주소:** 데이터를 오퍼랜드 필드에 직접 명시
    2.  **직접 주소:** 유효 주소를 오퍼랜드 필드에 직접 명시
    3.  **간접 주소:** 유효 주소의 주소를 명시 (가장 느림)
    4.  **레지스터 주소:** 데이터가 저장된 레지스터를 명시
    5.  **레지스터 간접 주소:** 유효 주소를 저장한 레지스터를 명시

#### 2-1. 확인 문제
1) 연산 코드 필드에는 메모리 주소만 담을 수 있다 (**X** - 연산 내용이 담김)  
2) 레지스터 간접 주소 지정 방식 결과: (1) **6** (2) **200**

## 🗓️ Day 2: CPU의 작동 원리

### 📌 Charter 4. CPU의 작동 원리
#### 1. ALU와 제어장치
* **ALU:** 레지스터와 제어장치로부터 피연산자와 제어 신호를 받아 산술/논리 연산 수행. 결과값과 플래그를 출력.
* **제어장치:** 클럭, 명령어, 플래그, 제어 신호를 바탕으로 내/외부 제어 신호를 발생.

#### 2. 레지스터 (핵심 종류)
* **프로그램 카운터(PC):** 메모리에서 가져올 명령어의 주소 저장
* **명령어 레지스터(IR):** 메모리에서 읽어 들인 명령어를 저장
* **메모리 주소 레지스터(MAR):** 메모리의 주소 저장
* **메모리 버퍼 레지스터(MBR):** 메모리와 주고받을 값을 저장
* **플래그 레지스터:** 연산 결과 또는 CPU 상태 정보 저장
* **범용 레지스터:** 데이터와 주소 모두 저장 가능
