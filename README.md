#### Chapter 1. 컴퓨터 구조
 컴퓨터가 이해하는 정보, 컴퓨터의 네 가지 핵심 부품

1. 컴퓨터가 이해하는 정보
- 데이터와 명령어로 이루어져 있다.

  데이터 : 컴퓨터가 이해하는 정적인 정보
  
  명령어 : 데이터를 움직이고 컴퓨터를 작동시키는 정보

  데이터  :1, 2 / 명령어 : 출력하라

2. 컴퓨터의 4가지 핵심 부품
- CPU, 메모리, 보조기억장치, 입출력장치
  1. CPU : 산술논리연산장치, 제어장치, 레지스터 등으로 이루어져 있으며 컴퓨터의 두뇌라고 봄.

- 확인문제
1) 컴퓨터가 이해하는 정보에는 데이터와 명령어가 있습니다.
2) 명령어를 해석하고 실행하는 장치 -> CPU
3) 프로그램이 실행되려면 반드시 메모리에 저장되어 있어야 합니다.
4) 보조기억장치 : 보관할 프로그램 저장 / 메모리 : 실행되는 프로그램 저장
5) 시스템 버스에 관련한 내용 

#### Charter 2. 데이터
2-1. 0과 1로 숫자를 표현하는 방법 : 이진법
- 0과 1을 나타내는 가장 작은 정보 단위를 비트라고 한다.
- ex) 2비트로 표현할 수 있는 정보
  0 0 / 0 1 / 1 0 / 1 1
- 따라서 n개의 비트로 표현 할 수 있는 상태는 2의 n승가지
- 비트는 가장 작은 단위이므로 프로그램의 크기를 말할 때는 비트보다 큰 단위인 바이트를 사용한다.
- 바이트 : 여덟 개의 비트를 묶은 단위. (1 byte = 8 bit, 2의 8승 개의 정보를 표현)
- 이진법으로 표현하기
- 0과 1로 음수 표현하기 : 2의 보수

- 확인문제
  1) 2000MB -> 2GB
  2) 1000GB = TB / 1000kB = 1MB / 1000MB = 1GB / 1024 bit

3-2. 명령어의 구조
- 명령어는 연산 코드와 오퍼랜드로 구성됨.

 * 명령어 주소 지정 방식 방법만 알면됨.
- 명령어 주소 지정 방식 : 유효 주소를 찾는 방법
  * 유효 주소 : 연산의 대상이 되는 데이터가 저장된 위치
- 1) 즉시 주소 : 연산에 사용할 데이터를 오퍼랜드 필드에 직접 명시
  2) 직접 주소 : 오퍼랜드 필드에 유효 주소를 직접 명시
  3) 간접 주소 : 유효 주소의 주소를 오퍼랜드 필드에 명시 (제일 느림)

        단, 레지스터 크기의 제한이 있을 수 있음.
  6) 레지스터 간접 주소 지정 : 연산에 사용할 데이터를 메모리에 저장, 그 주소(유효 주소)를 저장한 레지스터를 오퍼랜드 필드에 명시하는 방법 (간접 주소 지정방식보다 빠름)

### Charter 4. CPU의 작동 원리

- ALU
    - 레지스터를 통해 피연산자를 받아들이고, 제어장치로부터 수행할 연산을 알려주는 제어 신호를 받아 들인다.
    - ALU는 레지스터와 제어장치로부터 받아들인 피연산자와  제어 신호로 산술 연산, 논리 연산 등 다양한 연산을 수행
    - ALU는 연산 결과와 플래그를 내보낸다.!(부호 플래그, 제로 플래그, 캐리 플래그, 인터럽트 플래그, 슈퍼바이저 플래그!!)
- 제어장치
    - 클럭 신호를 받아들인다.
    - ‘해석해야 할 명령어’를 받아들인다.
    - 플래그 레지스터 속 플래그 값을 받아들인다.
    - 시스템 버스, 그중에서 제어 버스로 전달된 제어 신호를 받아들인다.
    - 제어장치는 CPU 내부와 외부로 제어 신호를 내보낸다.
- 확인 문제
    - 프로그램 카운터는 메모리에서 가져올 명령어의 주소, 명령어 레지스터는 해석할 명령어를 저장.
    - 메모리 주소 레지스터는 메모리의 주소, 메모리 버퍼 레지스터는 메모리와 주고받을 데이터를 저장.
    - 범용 레지스터는 데이터와 주소를 모두 저장, 플래그 레지스터는 연산 결과 혹은 CPU 상태에 대한 부가 정보를 저장.
    - 스택 포인터는 스택 최상단의 위치를 저장.
    - 베이스 레지스터에 저장된 기준 주소로서의 역할.
    - CPU의 ALU가 연산한 결과가 다음과 같을 때 계산 결과?
        - 플래그 레지스터 100000, 결과값 101
        - 답 ) 플래그 레지스터 순서 중 맨 앞자리는 부호 플래그로 1이면 음수이다. 따라서 101(2)는 011(2)에 2의 보수를 취하여 음수로 표현한 값이고, 011(2) 은 십진수 3이므로 결과값은 -3
- 레지스터
    - CPU 내부의 작은 임시저장장치
    - 프로그램 속 명령어 & 데이터는 실행 전후로 레지스터에 저장
    - CPU 내부에는 다양한 레지스터들이 있고, 각기 다른 역할을 가진다.
    - 반드시 알아야 할 레지스터!!! (단, CPU 종류마다 레지스터 종류는 다르다.)
        - 프로그램 카운터(PC,IP)
            - 메모리에서 가져올 명령어의 주소를 저장
        - 명령어 레지스터(IR)
            - 메모리에서 읽어 들인 명령어를 저장하는 레지스터
        - 메모리 주소 레지스터(MAR)
        - 메모리 버퍼 레지스터(MBR, MDR)
            - 메모리와 주고받을 값(데이터, 명령어..)을 저장
        - 플래그 레지스터
            - 연산 결과 또는 CPU 상태에 대한 부가적인 정보
        - 범용 레지스터
            - 자유롭게 사용
        - 스택 포인터
            - 스택 주소 지정 방식에 사용
        - 베이스 레지스터
            - 연산 결과 또는 CPU 상태에 대한 부가적인 정보 저장, 베이스 주소 지정 방식에 사용
    - 주소 지정 방식
        - 스택 주소 지정 방식
        - 변위 주소 지정 방식 : 오퍼랜드 필드의 값(변위)과 특정 레지스터의 값을 더하여 유효 주소를 얻음.
            - 상대 주소 지정 방식
                - 오퍼랜드와 프로그램 카운터의 값을 더하여 유효 주소를 얻음.
            - 베이스 레지스터 주소 지정 방식
                - 오퍼랜드와 베이스  레지스터의 값을 더하여 유효 주소를 얻음.
            - 확인 문제
                - 프로그램 카운터는 **다음에** 실행할 명령어의 주소를 저장!!
- 명령어 사이클과 인터럽트
    - 명령어 사이클
        - 인출 사이클, 실행 사이클, 간접 사이클, 인터럽트를 거쳐서 명령어가 실행된다.

### Charter 5. CPU 성능 향상 기법

- 클럭
    - 컴퓨터 부품들은 ‘클럭 속도’에 맞춰 움직인다.
    - 클럭 속도가 높아지면 CPU는 명령어 사이클을 더 빠르게 반복한다.
    - 클럭 속도는 헤르츠(Hz) 단위로 측정. (1초에 클럭이 몇 번 반복되는지)
    - 그러나 클럭 속도만 늘린다고 CPU가 빨라지지는 않는다. 무작정 높이면 발열 문제 심각. ——> 해결법은 코어 수를 늘리거나 스레드 수를 늘리는 방안이 있다.
- 코어와 멀티코어
    - 코어?
        - CPU : 명령어를 실행하는 부품을 여러 개 포함하는 부품 으로 오늘날 코어로 불린다.
    - 멀티코어
        - 듀얼→트리플→쿼드→헥사→옥타→데카→도데카…. 굳이 외울 필요는…없다..
- 스레드와 멀티스레드
    - 스레드
        - 하드웨어적 스레드
            - 하나의 코어가 동시에 처리하는 명령어의 단위
            - *하이퍼스레딩 : 인텔의 멀티스레드 기술.
        - 소프트웨어적 스레드 ? 실행 흐름의 단위!
            - 하나의 프로그램에서 독립적으로 실행되는 단위
    - 멀티스레드 프로세서
        - 멀티코어 프로세서 ： 명령어를 실행할 수 있는 하드웨어 부품이 CPU안에 두 개 이상 있는 CPU
        - 멀티스레드 프로세서 ： 하나의 코어로 여러개의 명령어를 동시에 실행할 수 있는 CPU
- 확인문제
    - 클럭 신호는 CPU의 속도 단위 입니다.
    - 스레드는 코어가 처리할 수 있는 작업 단위입니다.
- 명령어 파이프라인
    - 명령어 처리 과정을 클럭 단위로 나누어 보면 아래와 같이 나눌 수 있다.
        1. 명령어 인출(Instruction Fetch)
        2. 명령어 해석(Instruction Decode)
        3. 명령어 실행(Execute Instruction)
        4. 결과 저장(Write Back)
    - 같은 단계가 겹치지만 않는 다면 CPU는 ‘각 단계를 동시에 실행할 수 있다’
    - 파이프라인 위험에는 3가지 위험이 있다.
        - 데이터 위험
            - 이전 명령어의 데이터에 의존하는 경우
        - 제어 위험
            - 기본적으로 PC는 ‘현재 실행중인 명령어의 다음 주소’로 갱신되나 분기 등으로 ‘PC의 갑작스러운 변화로 실행 흐름이 변경되는 경우
        - 구조적 위험(=자원 위험)
            - 서로 다른 명령어가 동시에 ALU, 레지스터 등과 같은 CPU 부품을 사용하려고 하는 경우
- 슈퍼스칼라
    - 여러 개의 명령어 파이프라인을 포함한 구조
- 비순차적 명령어 처리(OoOE)
    - 명령어의 합법적인 새치기
    - 명령어들 중에 서로 데이터 의존성이 없는 명령어를 미리 처리함.(의존성 있는 경우 기다려야 하므로)
- 명령어 집합
    - 명령어 집합 또는 명령어 집합 구조(ISA, Instruction Set Architecture)가 다르면 CPU가 이해할 수 있는 명령어가 다르다는 뜻이고, 명령어가 달라지면 어셈블리어도 달라진다.
    - ISA가 같은 CPU끼리는 서로의 명령어를 이해할 수 있지만, ISA가 다르면 서로의 명령어를 이해하지 못한다.
    - 명령어 병렬 처리 기법들을 도입하기 유리한 ISA의 양대산맥 CISC vs RISC
        - CISC(Complex Instruction Set Computer)
            - 복잡하고 다양한 수의 가변 길이 명령어를 활용
            - 상대적으로 적은 수의 명령어로 프로그램 실행
            - 명령어의 크기와 실행되기까지의 시간이 일정하지 않음.
            - 명령어를 실행하는 데에 여러 클럭 주기를 필요로 함.
            - 다양한 주소 지정 방식
        - RISC(Reduced Instrction Set Computer)
            - 단순하고 적은 수의 고정 길이 명령어를 활용
            - 상대적으로 많은 명령어의 수
            - 1클럭 내외로 명령어를 수행하여 파이프라이닝에 최적화
            - CISC보다 적은 주소 지정 방식
