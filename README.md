#### Chapter 1. 컴퓨터 구조
 컴퓨터가 이해하는 정보, 컴퓨터의 네 가지 핵심 부품

1. 컴퓨터가 이해하는 정보
- 데이터와 명령어로 이루어져 있다.

  데이터 : 컴퓨터가 이해하는 정적인 정보
  
  명령어 : 데이터를 움직이고 컴퓨터를 작동시키는 정보

  데이터  :1, 2 / 명령어 : 출력하라

2. 컴퓨터의 4가지 핵심 부품
- CPU, 메모리, 보조기억장치, 입출력장치
  1. CPU : 산술논리연산장치, 제어장치, 레지스터 등으로 이루어져 있으며 컴퓨터의 두뇌라고 봄.

- 확인문제
1) 컴퓨터가 이해하는 정보에는 데이터와 명령어가 있습니다.
2) 명령어를 해석하고 실행하는 장치 -> CPU
3) 프로그램이 실행되려면 반드시 메모리에 저장되어 있어야 합니다.
4) 보조기억장치 : 보관할 프로그램 저장 / 메모리 : 실행되는 프로그램 저장
5) 시스템 버스에 관련한 내용 

#### Charter 2. 데이터
2-1. 0과 1로 숫자를 표현하는 방법 : 이진법
- 0과 1을 나타내는 가장 작은 정보 단위를 비트라고 한다.
- ex) 2비트로 표현할 수 있는 정보
  0 0 / 0 1 / 1 0 / 1 1
- 따라서 n개의 비트로 표현 할 수 있는 상태는 2의 n승가지
- 비트는 가장 작은 단위이므로 프로그램의 크기를 말할 때는 비트보다 큰 단위인 바이트를 사용한다.
- 바이트 : 여덟 개의 비트를 묶은 단위. (1 byte = 8 bit, 2의 8승 개의 정보를 표현)
- 이진법으로 표현하기
- 0과 1로 음수 표현하기 : 2의 보수

- 확인문제
  1) 2000MB -> 2GB
  2) 1000GB = TB / 1000kB = 1MB / 1000MB = 1GB / 1024 bit

3-2. 명령어의 구조
- 명령어는 연산 코드와 오퍼랜드로 구성됨.

 * 명령어 주소 지정 방식 방법만 알면됨.
- 명령어 주소 지정 방식 : 유효 주소를 찾는 방법
  * 유효 주소 : 연산의 대상이 되는 데이터가 저장된 위치
- 1) 즉시 주소 : 연산에 사용할 데이터를 오퍼랜드 필드에 직접 명시
  2) 직접 주소 : 오퍼랜드 필드에 유효 주소를 직접 명시
  3) 간접 주소 : 유효 주소의 주소를 오퍼랜드 필드에 명시 (제일 느림)

        단, 레지스터 크기의 제한이 있을 수 있음.
  6) 레지스터 간접 주소 지정 : 연산에 사용할 데이터를 메모리에 저장, 그 주소(유효 주소)를 저장한 레지스터를 오퍼랜드 필드에 명시하는 방법 (간접 주소 지정방식보다 빠름)

### Charter 4. CPU의 작동 원리

- ALU
    - 레지스터를 통해 피연산자를 받아들이고, 제어장치로부터 수행할 연산을 알려주는 제어 신호를 받아 들인다.
    - ALU는 레지스터와 제어장치로부터 받아들인 피연산자와  제어 신호로 산술 연산, 논리 연산 등 다양한 연산을 수행
    - ALU는 연산 결과와 플래그를 내보낸다.!(부호 플래그, 제로 플래그, 캐리 플래그, 인터럽트 플래그, 슈퍼바이저 플래그!!)
- 제어장치
    - 클럭 신호를 받아들인다.
    - ‘해석해야 할 명령어’를 받아들인다.
    - 플래그 레지스터 속 플래그 값을 받아들인다.
    - 시스템 버스, 그중에서 제어 버스로 전달된 제어 신호를 받아들인다.
    - 제어장치는 CPU 내부와 외부로 제어 신호를 내보낸다.
- 확인 문제
    - 프로그램 카운터는 메모리에서 가져올 명령어의 주소, 명령어 레지스터는 해석할 명령어를 저장.
    - 메모리 주소 레지스터는 메모리의 주소, 메모리 버퍼 레지스터는 메모리와 주고받을 데이터를 저장.
    - 범용 레지스터는 데이터와 주소를 모두 저장, 플래그 레지스터는 연산 결과 혹은 CPU 상태에 대한 부가 정보를 저장.
    - 스택 포인터는 스택 최상단의 위치를 저장.
    - 베이스 레지스터에 저장된 기준 주소로서의 역할.
    - CPU의 ALU가 연산한 결과가 다음과 같을 때 계산 결과?
        - 플래그 레지스터 100000, 결과값 101
        - 답 ) 플래그 레지스터 순서 중 맨 앞자리는 부호 플래그로 1이면 음수이다. 따라서 101(2)는 011(2)에 2의 보수를 취하여 음수로 표현한 값이고, 011(2) 은 십진수 3이므로 결과값은 -3
- 레지스터
    - CPU 내부의 작은 임시저장장치
    - 프로그램 속 명령어 & 데이터는 실행 전후로 레지스터에 저장
    - CPU 내부에는 다양한 레지스터들이 있고, 각기 다른 역할을 가진다.
    - 반드시 알아야 할 레지스터!!! (단, CPU 종류마다 레지스터 종류는 다르다.)
        - 프로그램 카운터(PC,IP)
            - 메모리에서 가져올 명령어의 주소를 저장
        - 명령어 레지스터(IR)
            - 메모리에서 읽어 들인 명령어를 저장하는 레지스터
        - 메모리 주소 레지스터(MAR)
        - 메모리 버퍼 레지스터(MBR, MDR)
            - 메모리와 주고받을 값(데이터, 명령어..)을 저장
        - 플래그 레지스터
            - 연산 결과 또는 CPU 상태에 대한 부가적인 정보
        - 범용 레지스터
            - 자유롭게 사용
        - 스택 포인터
            - 스택 주소 지정 방식에 사용
        - 베이스 레지스터
            - 연산 결과 또는 CPU 상태에 대한 부가적인 정보 저장, 베이스 주소 지정 방식에 사용
    - 주소 지정 방식
        - 스택 주소 지정 방식
        - 변위 주소 지정 방식 : 오퍼랜드 필드의 값(변위)과 특정 레지스터의 값을 더하여 유효 주소를 얻음.
            - 상대 주소 지정 방식
                - 오퍼랜드와 프로그램 카운터의 값을 더하여 유효 주소를 얻음.
            - 베이스 레지스터 주소 지정 방식
                - 오퍼랜드와 베이스  레지스터의 값을 더하여 유효 주소를 얻음.
            - 확인 문제
                - 프로그램 카운터는 **다음에** 실행할 명령어의 주소를 저장!!
- 명령어 사이클과 인터럽트
    - 명령어 사이클
        - 인출 사이클, 실행 사이클, 간접 사이클, 인터럽트를 거쳐서 명령어가 실행된다.

### Charter 5. CPU 성능 향상 기법

- 클럭
    - 컴퓨터 부품들은 ‘클럭 속도’에 맞춰 움직인다.
    - 클럭 속도가 높아지면 CPU는 명령어 사이클을 더 빠르게 반복한다.
    - 클럭 속도는 헤르츠(Hz) 단위로 측정. (1초에 클럭이 몇 번 반복되는지)
    - 그러나 클럭 속도만 늘린다고 CPU가 빨라지지는 않는다. 무작정 높이면 발열 문제 심각. ——> 해결법은 코어 수를 늘리거나 스레드 수를 늘리는 방안이 있다.
- 코어와 멀티코어
    - 코어?
        - CPU : 명령어를 실행하는 부품을 여러 개 포함하는 부품 으로 오늘날 코어로 불린다.
    - 멀티코어
        - 듀얼→트리플→쿼드→헥사→옥타→데카→도데카…. 굳이 외울 필요는…없다..
- 스레드와 멀티스레드
    - 스레드
        - 하드웨어적 스레드
            - 하나의 코어가 동시에 처리하는 명령어의 단위
            - *하이퍼스레딩 : 인텔의 멀티스레드 기술.
        - 소프트웨어적 스레드 ? 실행 흐름의 단위!
            - 하나의 프로그램에서 독립적으로 실행되는 단위
    - 멀티스레드 프로세서
        - 멀티코어 프로세서 ： 명령어를 실행할 수 있는 하드웨어 부품이 CPU안에 두 개 이상 있는 CPU
        - 멀티스레드 프로세서 ： 하나의 코어로 여러개의 명령어를 동시에 실행할 수 있는 CPU
- 확인문제
    - 클럭 신호는 CPU의 속도 단위 입니다.
    - 스레드는 코어가 처리할 수 있는 작업 단위입니다.
- 명령어 파이프라인
    - 명령어 처리 과정을 클럭 단위로 나누어 보면 아래와 같이 나눌 수 있다.
        1. 명령어 인출(Instruction Fetch)
        2. 명령어 해석(Instruction Decode)
        3. 명령어 실행(Execute Instruction)
        4. 결과 저장(Write Back)
    - 같은 단계가 겹치지만 않는 다면 CPU는 ‘각 단계를 동시에 실행할 수 있다’
    - 파이프라인 위험에는 3가지 위험이 있다.
        - 데이터 위험
            - 이전 명령어의 데이터에 의존하는 경우
        - 제어 위험
            - 기본적으로 PC는 ‘현재 실행중인 명령어의 다음 주소’로 갱신되나 분기 등으로 ‘PC의 갑작스러운 변화로 실행 흐름이 변경되는 경우
        - 구조적 위험(=자원 위험)
            - 서로 다른 명령어가 동시에 ALU, 레지스터 등과 같은 CPU 부품을 사용하려고 하는 경우
- 슈퍼스칼라
    - 여러 개의 명령어 파이프라인을 포함한 구조
- 비순차적 명령어 처리(OoOE)
    - 명령어의 합법적인 새치기
    - 명령어들 중에 서로 데이터 의존성이 없는 명령어를 미리 처리함.(의존성 있는 경우 기다려야 하므로)
- 명령어 집합
    - 명령어 집합 또는 명령어 집합 구조(ISA, Instruction Set Architecture)가 다르면 CPU가 이해할 수 있는 명령어가 다르다는 뜻이고, 명령어가 달라지면 어셈블리어도 달라진다.
    - ISA가 같은 CPU끼리는 서로의 명령어를 이해할 수 있지만, ISA가 다르면 서로의 명령어를 이해하지 못한다.
    - 명령어 병렬 처리 기법들을 도입하기 유리한 ISA의 양대산맥 CISC vs RISC
        - CISC(Complex Instruction Set Computer)
            - 복잡하고 다양한 수의 가변 길이 명령어를 활용
            - 상대적으로 적은 수의 명령어로 프로그램 실행
            - 명령어의 크기와 실행되기까지의 시간이 일정하지 않음.
            - 명령어를 실행하는 데에 여러 클럭 주기를 필요로 함.
            - 다양한 주소 지정 방식
        - RISC(Reduced Instrction Set Computer)
            - 단순하고 적은 수의 고정 길이 명령어를 활용
            - 상대적으로 많은 명령어의 수
            - 1클럭 내외로 명령어를 수행하여 파이프라이닝에 최적화
            - CISC보다 적은 주소 지정 방식
         
- ### Charter 6. 메모리와 캐시 메모리

- RAM의 특징과 종류
    - 특징
        - 휘발성 저장 장치
    - 종류
        - DRAM(Dynamic RAM)
            - 저장된 데이터가 동적으로 사라짐, 일정 주기로 재활성화 필요, but 소비 전력이 낮고 저렴, 집적도가 높아 대용량 설계 용이
            - 주기억장치(RAM)에 주로 사용
        - SRAM(Static RAM)
            - 저장된 데이터가 정적인(사라지지 않는) RAM, DRAM보다 빠름
            - 캐시 메모리에 사용
        - SDRAM(Synchronous Dynamic RAM)
            - 클럭과 동기화된 DRAM = 클럭 타이밍에 맞춰 CPU와 정보를 주고 받을 수 있다.
        - DDR SDRAM(Double Data Rate SDRAM)
            - 대역 폭을 넓혀 속도를 빠르게 만든 SDRAM, 가장 흔히 사용됨.
            - 대역폭은 데이터를 주고 받는 길의 너비
        - 확인문제
            - RAM은 휘발성 저장 장치, 보조기억장치는 비휘발성 저장 장치
            - DRAM은 시간이 지나면 저장된 데이터가 점차 사리지며, SRAM은 시간이 지나도 사라지지 않는다.
            - SDRAM은 클럭과 동기화된 DRAM
            - DDR SDRAM은 SDR SDRAM에 비해 대역폭이 두 배 넓다.
- 메모리의 주소 공간
    - 물리 주소와 논리 주소
        - 물리 주소는 메모리 하드웨어 상의 주소이고, 논리 주소는 CPU와 실행 중인 프로그램이 사용하는 주소이다.
        - 논리 주소와 물리 주소 간의 변환은 CPU와 주소 버스 사이에 위치한 메모리 관리 장치(MMU, Memory Management Unit)라는 하드웨어에 의해 수행
    - 메모리 보호 기법
        - 다른 프로그램의 영역을 침법할 수 있는 명령어를 방지하고 실행 중인 프로그램이 다른 프로그램에 영향을 받지 않도록 보호하기 위해 한계 레지스터가 나타남.
        - 베이스 레지스터 값 ≤ 프로그램의 물리 주소 범위 ≤ 베이스 레지스터 값+한계 레지스터 값
    - 확인 문제
        - 물리 주소는 메모리 하드웨어상의 주소, 논리 주소는 CPU와 실행 중인 프로그램이 사용하는 주소
        - MMU는 논리 주소를 물리 주소로 변환함.
        - 베이스 레지스터는 프로그램의 첫 물리 주소를 저장
        - 한계 레지스터는 실행 중인 프로그램의 논리 주소의 최대 크기를 저장.
- 캐시 메모리
    - 저장 장치 계층 구조
        - CPU와 가까운 저장 장치는 빠르다.
            1. 캐시메모리
            2. 메모리
            3. 보조기억장치
        - 위의 순으로 속도가 빠르며, 용량이 작고, 가격은 비싸다.
    - 캐시 메모리
        - CPU가 메모리에 접근하는 속도는 레지스터에 접근하는 속도보다 느림. 그래서 캐시 메모리가 등장!
        - CPU와 메모리 사이에 위치하고, 레지스터보다 용량이 크고 메모리보다 빠른 SRAM 기반의 저장 장치
        - 계층
            - 코어(CPU)와 가까움 - L1 - L2 - L3
        - 캐시 적중률을 높여야 함
            - 참조 지역성의 원리에 의해 CPU,가 사용할 법한 데이터를 예측.
                - 시간 지역성 : 최근에 접근했던 메모리 공간에 다시 접근
                - 공간 지역성 : 접근한 메모리 공간 근처를 접근
    - 확인 문제
        - 캐시 적중률이 높으면 CPU의 메모리 접근 횟수를 줄일 수 있다.

    - RAID는 주로 하드 디스크와 SSD를 사용하는 기술로 데이터의 안전성 혹은 높은 성능을 위해 여러 개의 물리적 보조기억장치를 하나로 사용하는 기술
    - 종류
        - RAID 0
            - 데이터를 단순히 나누어 저장하는 구성 방식
            - 스트라입(Stripe) : 분산되어 저장된 데이터
            - 스트라이핑(Striping) : 분산하여 저장
        - RAID 1
            - 미러링 : 복사본을 만드는 방식
            - 데이터를 쓸 때 원본과 복사본 두 군데에 씀 ( 느린 쓰기 속도)
        - ~~RAID 2~~
        - ~~RAID 3~~
        - RAID 4
            - 오류를 검출하고 복구하기 위한 정보(패리티 비트)를 저장
        - RAID 5
            - RAID 4 에서 패리티 저장 장치 병목 현상 발생 해소
            - 패리티 정보를 분산하여 저장
        - RAID 6
            - 기본 구성은 RAID 5 와 같으나 두 종류의 패리티를 두는 방식
            - RAID 5 보다 안전, 쓰기는 RAID 5 보다 느림

    - RAID란 데이터의 안전성 혹은 높은 성능을 위해 여러 하드 디스크나 SSD를 마치 하나의 장치처럼 사용하는 기술
    - RAID 0는 데이터를 단순히 병렬로 분산하여 저장하고, RAID 1은 완전한 복사본을 만든다.
    - RAID 4는 패리티를 저장한 장치를 따로 두는 방식이고, RAID 5는 패리티를 분산하여 저장하는 방식
    - RAID 6는 서로 다른 두 개의 패리티를 두는 방식

### Charter 8. 입출력장치

- 장치 컨트롤러
    - 필요한 이유?
        - 입출력장치의 종류가 너무 다양해 정보를 주고받는 방식을 규격화 하기 어려움
        - CPU와 메모리의 데이터 전송률은 높지만 입출력장치의 데이터 전송률이 낮음.
    - 입출력장치는 위와 같은 이유로 컴퓨터에 직접 연결되지 않고 장치 컨트롤러라는 하드웨어를 통해 연결된다.
        - 역할
            - CPU와 입출력장치 간의 통신 중개
            - 오류 검출
            - 데이터 버퍼링
        - 내부 구조
            - 데이터 레지스터
            - 상태 레지스터
            - 제어 레지스터
- 장치 드라이버
    - 장치 컨트롤러의 동작을 감지하고 제어하는 프로그램
- 확인 문제
    - 입출력장치는 장치 컨트롤러를 통해 컴퓨터 내부와 정보를 주고 받는다.
    - 장치 드라이버는 장치 컨트롤러가 컴퓨터 내부와 정보를 주고 받을 수 있게 하는 프로그램.
    - 컴퓨터가 장치 드라이버를 인식하고 실행할 수 있다면 해당 입출력장치의 사용이 가능.
- 프로그램 입출력
    - 프로그램 속 명령어로 입출력장치를 제어하는 방법
    - 입출력 명령어로써 장치 컨트롤러와 상호작용
    - CPU가 여러 장치 컨트롤러 속 레지스터들을 모두 알기 어려운데 이를 알기 위한 2가지 방식이 있다.
        - 메모리 맵 입출력
            - 메모리 접근 주소 공간과 입출력장치 접근 주소 공간을 하나로 인식
            - 어느 주소든 메모리 주소를 대하듯 하면 되기 때문에 명령어가 같다.
        - 고립형 입출력
            - 위의 두 개의 주소 공간을 분리
            - 입출력장치 전용 명령어 사용
- 인터럽트 기반 입출력
    - 동시다발적인 인터럽트 : 우선순위를 반영한 인터럽트
        - 프로그래머블 인터럽트 컨트롤러(PIC, Programmable Interrupt Controller) 라는 하드웨어를 사용한다.
        - 단, PIC가 무시할 수 없는 인터럽트인 NMI까지 우선순위를 판별하지 않는다
- DMA 입출력
    - 입출력장치와 메모리가 CPU를 거치지 않고도 상호작용할 수 있는 입출력 방식
    - 직접 메모리에 접근할 수 있는 입출력 기능(Direct Memory Access)
    - DMA 입출력을 하기 위해서는 시스템 버스에 연결된 DMA 컨트롤러라는 하드웨어가 필요.
        - 입출력 버스
            - DMA를 위해 시스템 버스를 너무 자주 사용하면 그만큼 CPU가 시스템 버스를 이용하지 못하는 단점.
            - 위 문제를 해결하기 위해 DMA 컨트롤러와 장치 컨트롤러들을 입출력 버스라는 별도의 버스에 연결하여 해결.
            - 종류
                - PCI 버스, PCI Express (PCle) 버스 등..
- 확인 문제
    - 입출력 버스는 입출력장치와 컴퓨터 내부를 연결 짓는 통로로, 입출력 작업 과정에서 시스템 버스 사용 횟수를 줄여준다.
    - DMA 컨트롤러와 CPU는 시스템 버스를 통시에 사용할 수 없다.
    - DMA 컨트롤러는 CPU를 거치지 않고 메모리와 입출력장치 간의 데이터를 주고 받는다.
  ### Charter 9. 운영체제 시작하기

- 운영체제란
    - 모든 프로그램은 실행되기 위한 자원이 필요하다. 실행할 프로그램에 필요한 자원을 할당하고, 프로그램이 실행되도록 돕는 특별한 프로그램
    - 운영체제는 컴퓨터가 부팅될 때 메모리 내 커널 영역이라는 공간에 적재되어 실행된다.
    - 커널 영역을 제외한 영역을 사용자가 이용하는 응용 프로그램이 적재되는 영역으로 사용자 영역이라고 한다.
    - 운영체제는 커널 영역에 적재되어 사용자 영역에 적재된 프로그램들에 자원을 할당하고 이들이 올바르게 실행되도록 돕는다.
- 운영체제의 심장, 커널
    - 운영체제는 사용자가 실행하는 프로그램을 위한 프로그램으로 이러한 운영체제의 핵심 서비스를 담당하는 부분을 커널이라고 한다.
- 이중 모드와 시스템 호출
    - 이중 모드
        - CPU가 명령어를 실행하는 모드를 커널 모드와 사용자 모드로 구분하는 방식
        - 사용자 모드
            - 운영체제 서비스를 제공받을 수 없는 실행 모드
            - 자원 접근 불가
    - 시스템 호출
        - 사용자 모드로 실행되는 프로그램이 운영체제 서비스를 제공 받으려면 커널 모드로 전환되어야 한다.
        - 운영체제 서비스를 제공받기 위한 요청을 시스템 호출(시스템 콜)이라고 한다.
        - 시스템 호출은 일종의 인터럽트로 소프트웨어 인터럽트라고 한다.
- 운영체제의 핵심 서비스
    - 프로세스 관리
        - 프로세스 - 실행 중인 프로그램
        - 프로세스와 스레드, 프로세스 동기화, 교착상태 해결
    - 자원 접근 및 할당
 
- 확인 문제
    - 시스템 호출은 운영체제의 서비스를 제공받기 위해 커널 모드로 전환하는 방법.
    - 대표적인 운영체제 서비스로 프로세스 관리, 자원 접근 및 할당, 파일 시스템 관리가 있다.

### Charter 10. 프로세스와 스레드

- 프로세스 확인
    - 포그라운드 프로세스
    - 백그라운드 프로세스
- 프로세스 제어 블록
    - CPU의 자원이 한정적이므로 운영체제는 프로세스의 실행 순서를 관리하고, 프로세스에 CPU를 비롯한 자원을 배분하기 위해 프로세스 제어 블록(PCB)를 이용한다.
    - PCB의 정보
        - 프로세스 ID(PID)
        - 레지스터 값
            - 해당 프로세스가 실행하며 사용했던 PC를 비롯한 값들이 포함.
        - 프로세스 상태
        - CPU 스케줄링 정보
        - 메모리 관리 정보
            - 베이스 레지스터, 한계 레지스터 값과 같은 정보들 담김, 프로세스의 주소를 알기 위한 페이지 테이블 정보 포함.
        - 사용한 파일과 입출력장치 목록
- 문맥 교환
    - 기존의 프로세스 문맥을 PCB에 백업하고, 새로운 프로세스를 실행하기 위해 문맥을 PCB로부터 복구하여 새로운 프로세스를 실행하는 것
- 프로세스의 메모리 영역
    - 프로세스가 생성되면 커널 영역에 PCB가 생성.
    - 사용자 영역에는 코드 영역, 데이터 영역, 힙 영역, 스택 영역으로 나뉘어 저장.
        - 정적 할당 영역
            - 코드 영역
                - 기계어로 이루어진 명령어 저장, 쓰기 금지, 읽기 전용
            - 데이터 영역
                - 전역 변수가 대표적
        - 동적 할당 영역
            - 힙 영역
                - 프로그래머가 직접 할당할 수 있는 저장 공간
                - 사용 후 메모리 공간을 반환하지 않으면 메모리 누수가 발생 가능
                - 낮은 주소 → 높은 주소로 할당.
            - 스택 영역
                - 데이터를 일시적으로 저장하는 공간
                - 매개 변수, 지역 변수가 대표적
                - 높은 주소 → 낮은 주소로 할당.
    - 데이터, 힙, 스택 영역의 차이?!
        - 각각의 영역은 프로그램이 실행될 때 메모리를 효율적으로 나눠 쓰는 방법으로 데이터의 수명과 누가 관리하느냐에 따라 구분된다.
        **데이터 영역** - 전역 변수, 정적 변수를 저장, 프로그램 시작 시 할당~종료시 해제, 관리주체는 시스템(자동)
        **힙 영역** - 사용자가 직접 할당하는 데이터, 런타임 중 필요할 때 ~ 명시적 해제, 관리주체는 프로그래머
        **스택 영역** - 지역 변수, 매개변수, 리턴 주소, 함수 호출 시 할당 ~ 함수 종료시 해제, 관리주체는 시스템(자동)
        - 동적 할당 영역인 힙, 스택 영역의 할당 방향이 다른 이유는 한정된 메모리 공간을 최대한 효율적이고 유연하게 사용하기 위해서이다. 서로 마주 보는 구조로 설계하여 중간에 공유할 수 있는 가용 공간을 두어 충돌 방지 및 관리의 용이성이 생긴다.
