## <a id="day-1-컴퓨터-구조--데이터--명령어"></a> Day 1

### 📌 Chapter 1. 컴퓨터 구조

#### 1. 컴퓨터가 이해하는 정보
* **데이터:** 숫자, 문자, 이미지 등 정적인 정보
* **명령어:** 데이터를 움직이고 작동시키는 정보 (ex. 1과 2를 출력하라. 데이터 : 1, 2 / 명령어 : 출력하라)

#### 2. 핵심 부품 4가지
1. **CPU:** 산술논리연산장치, 제어장치, 레지스터로 구성 (컴퓨터의 두뇌)
2. **메모리:** 실행 중인 프로그램의 명령어와 데이터 저장
3. **보조기억장치:** 전원이 꺼져도 저장 (HDD, SSD)
4. **입출력장치:** 마이크, 스피커, 키보드 등

#### 3. 확인문제
1. 컴퓨터가 이해하는 정보에는 데이터와 명령어가 있습니다.
2. 명령어를 해석하고 실행하는 장치 -> CPU
3. 프로그램이 실행되려면 반드시 메모리에 저장되어 있어야 합니다.
4. 보조기억장치 : 보관할 프로그램 저장 / 메모리 : 실행되는 프로그램 저장
5. 시스템 버스에 관련한 내용

### 📌 Charter 2. 데이터

#### 1. 0과 1로 숫자를 표현하는 방법 : 이진법
- 0과 1을 나타내는 가장 작은 정보 단위를 **비트**라고 한다.
- ex) 2비트로 표현할 수 있는 정보: 0 0 / 0 1 / 1 0 / 1 1
- 따라서 n개의 비트로 표현 할 수 있는 상태는 2의 n승가지
- 비트는 가장 작은 단위이므로 프로그램의 크기를 말할 때는 비트보다 큰 단위인 바이트를 사용한다.
- 바이트 : 여덟 개의 비트를 묶은 단위. (1 byte = 8 bit, 2의 8승 개의 정보를 표현)
- 이진법으로 표현하기
- 0과 1로 음수 표현하기 : 2의 보수

#### 1-2 확인문제
1) 2000MB -> 2GB
2) 1000GB = TB / 1000kB = 1MB / 1000MB = 1GB / 1024 bit

#### 2. 0과 1로 문자를 표현하는 방법
- 문자 집합 : 컴퓨터가 이해할 수 있는 문자의 모음
- 인코딩 : 코드화하는 과정, 문자를 0과 1로 이루어진 문자코드로 변환
- 디코딩 : 코드를 해석하는 과정, 0과 1로 표현된 문자 코드를 문자로 변환
- 아스키 코드 : 7비트로 하나의 문자 표현(총 8비트인데 1비트는 오류검출을 위한 패리티 비트)
- EUC-KR : 문자 집합을 기반으로 하는 대표적인 완성형 인코딩 방식
- 유니코드 : 통일된 문자 집합, 한글, 영어, 화살표와 같은 특수 문자, 심지어 이모티콘까지
- 유니코드의 인코딩 방식 : utf-8, utf-16 등..

### 📌 Charter 3. 명령어

#### 1. 소스 코드와 명령어
- 고급 언어와 저급 언어
    1) 고급 언어 : 사람을 위한 언어
    2) 저급 언어 : 기계어, 어셈블리어
    ex) 기계어 -> 어셈블리어: 0101 0101 -> push rbp / 0101 1101 -> pop rbp / 1100 0011 -> ret
- 컴파일 언어와 인터프리터 언어
    * 컴파일 ? 컴파일 언어로 작성된 소스 코드가 저급 언어로 변환되는 과정
    1) 컴파일 언어 : 컴파일러를 통해 저급 언어로 변환된 언어로 한꺼번에 실행
    2) 인터프리터 언어 : 인터프리터에 의해 소스 코드가 한 줄씩 실행되는 고급 언어, 대화형 가능
- C 언어 컴파일 과정
    test.c -> [전처리기] -> test.i -> [컴파일러] -> test.s -> [어셈블러] -> test.0 -> [링커] -> test.exe

#### 1-2. 확인문제
1) 고급 언어가 아닌 것은? 기계어,어셈블리어
2) 
    > 1. 컴파일 언어는 한 줄이라도 소스 코드상에 오류가 있다면 실행x
    > 2. 일반적으로 컴파일 언어보다 인터프리터 언어가 빠르다 -> 인터프리터 언어가 더 느리다
    > 3. 인터프리터는 인터프리터 언어로 작성된 소스 코드를 한 줄씩 저급 언어로 변환하여 실행
    > 4. 컴파일러는 컴파일언어로 작성된 소스 코드 전체를 목적 코드로 변환

#### 2. 명령어의 구조
- 명령어는 연산 코드와 오퍼랜드로 구성됨.
- 연산 코드 : 명령어가 수행할 연산으로 MOVE, STORE, LOAD(FETCH), PUSH, POP 등이 있다.
- 오퍼랜드 : 연산에 사용할 데이터가 저장된 위치
- 주소 지정 방식 : 즉시 주소, 직접 주소, 간접 주소, 레지스터 주소, 레지스터 간접 주소 지정 방식
    * 명령어 주소 지정 방식 방법만 알면됨.
- 명령어 주소 지정 방식 : 유효 주소를 찾는 방법
    * 유효 주소 : 연산의 대상이 되는 데이터가 저장된 위치
    > 1) 즉시 주소 : 연산에 사용할 데이터를 오퍼랜드 필드에 직접 명시
    > 2) 직접 주소 : 오퍼랜드 필드에 유효 주소를 직접 명시
    > 3) 간접 주소 : 유효 주소의 주소를 오퍼랜드 필드에 명시 (제일 느림)
    > 4) 레지스터 주소 : 연산에 사용될 데이터를 저장한 레지스터를 오퍼랜드 필드에 직접 명시
    > -> 일반적으로 CPU 외부의 메모리에 접근하는 것보다 CPU 내부의 레지스터에 접근하는 것이 빠름. 단, 레지스터 크기의 제한이 있을 수 있음.
    > 6) 레지스터 간접 주소 지정 : 연산에 사용할 데이터를 메모리에 저장, 그 주소(유효 주소)를 저장한 레지스터를 오퍼랜드 필드에 명시하는 방법 (간접 주소 지정방식보다 빠름)

#### 2-1. 확인 문제
1) 명령어에 대한 설명
    - 명령어는 연산 코드와 오퍼랜드로 구성
    - 연산 코드 필드에는 메모리 주소만 담을 수 있다 (X) => 연산 코드 필드에는 명령어가 수행할 내용이 담긴다.
    - 오퍼랜드 필드는 여러 개 있을 수 있다
    - 명령어에 연산에 사용할 데이터를 직접 명시할 경우 표현할 수 있는 데이터의 크기는 연산코드의 크기만큼 작아진다.
2) 레지스터 간접 주소 지정 방식으로 수행시: (1) 6 (2) 200

## <a id="day-2-cpu의-작동-원리--성능-향상-기법"></a> Day 2

### 📌 Charter 4. CPU의 작동 원리

- **ALU**
    - 레지스터를 통해 피연산자를 받아들이고, 제어장치로부터 수행할 연산을 알려주는 제어 신호를 받아 들인다.
    - ALU는 레지스터와 제어장치로부터 받아들인 피연산자와 제어 신호로 산술 연산, 논리 연산 등 다양한 연산을 수행
    - ALU는 연산 결과와 플래그를 내보낸다.!(부호 플래그, 제로 플래그, 캐리 플래그, 인터럽트 플래그, 슈퍼바이저 플래그!!)
- **제어장치**
    - 클럭 신호를 받아들인다.
    - ‘해석해야 할 명령어’를 받아들인다.
    - 플래그 레지스터 속 플래그 값을 받아들인다.
    - 시스템 버스, 그중에서 제어 버스로 전달된 제어 신호를 받아들인다.
    - 제어장치는 CPU 내부와 외부로 제어 신호를 내보낸다.
- **확인 문제**
    - 프로그램 카운터는 메모리에서 가져올 명령어의 주소, 명령어 레지스터는 해석할 명령어를 저장.
    - 메모리 주소 레지스터는 메모리의 주소, 메모리 버퍼 레지스터는 메모리와 주고받을 데이터를 저장.
    - 범용 레지스터는 데이터와 주소를 모두 저장, 플래그 레지스터는 연산 결과 혹은 CPU 상태에 대한 부가 정보를 저장.
    - 스택 포인터는 스택 최상단의 위치를 저장.
    - 베이스 레지스터에 저장된 기준 주소로서의 역할.
    - CPU의 ALU가 연산한 결과가 다음과 같을 때 계산 결과?
        - 플래그 레지스터 100000, 결과값 101
        - 답 ) 플래그 레지스터 순서 중 맨 앞자리는 부호 플래그로 1이면 음수이다. 따라서 101(2)는 011(2)에 2의 보수를 취하여 음수로 표현한 값이고, 011(2) 은 십진수 3이므로 결과값은 -3
- **레지스터**
    - CPU 내부의 작은 임시저장장치
    - 프로그램 속 명령어 & 데이터는 실행 전후로 레지스터에 저장
    - CPU 내부에는 다양한 레지스터들이 있고, 각기 다른 역할을 가진다.
    - 반드시 알아야 할 레지스터!!! (단, CPU 종류마다 레지스터 종류는 다르다.)
        - 프로그램 카운터(PC,IP): 메모리에서 가져올 명령어의 주소를 저장
        - 명령어 레지스터(IR): 메모리에서 읽어 들인 명령어를 저장하는 레지스터
        - 메모리 주소 레지스터(MAR)
        - 메모리 버퍼 레지스터(MBR, MDR): 메모리와 주고받을 값(데이터, 명령어..)을 저장
        - 플래그 레지스터: 연산 결과 또는 CPU 상태에 대한 부가적인 정보
        - 범용 레지스터: 자유롭게 사용
        - 스택 포인터: 스택 주소 지정 방식에 사용
        - 베이스 레지스터: 연산 결과 또는 CPU 상태에 대한 부가적인 정보 저장, 베이스 주소 지정 방식에 사용
- **주소 지정 방식**
    - 스택 주소 지정 방식
    - 변위 주소 지정 방식 : 오퍼랜드 필드의 값(변위)과 특정 레지스터의 값을 더하여 유효 주소를 얻음.
        - 상대 주소 지정 방식: 오퍼랜드와 프로그램 카운터의 값을 더하여 유효 주소를 얻음.
        - 베이스 레지스터 주소 지정 방식: 오퍼랜드와 베이스 레지스터의 값을 더하여 유효 주소를 얻음.
    - 확인 문제: 프로그램 카운터는 **다음에** 실행할 명령어의 주소를 저장!!
- **명령어 사이클과 인터럽트**
    - 명령어 사이클: 인출 사이클, 실행 사이클, 간접 사이클, 인터럽트를 거쳐서 명령어가 실행된다.
    - 인터럽트
        - 동기 인터럽트(예외): 폴트 등
        - 비동기 인터럽트: 입출력 장치 인터럽트 요청 신호 발생 → CPU 에 보냄 → CPU의 실행사이클을 마치고 명령어를 인출 하기 전 인터럽트 여부 확인 → 인터럽트 요청 확인 → 인터럽트 플래그(1일 경우 가능!!)를 보고 여부 확인 → 인터럽트 받기 전 CPU 작업 백업 (현재 실행중이였던 프로그램 카운터 값 등 필요한 내용을 스택에 백업) → CPU는 인터럽트 벡터를 참조하여 인터럽트 서비스 루틴을 실행 → 백업한 작업을 복구
        - 막을 수 있는 인터럽트 / 막을 수 없는 인터럽트
    - 확인 문제
        - 명령어 사이클은 하나의 명령어가 처리되는 주기로, 인출, 실행, 간접, 인터럽트 사이클로 구성!!!
        - 인터럽트는 CPU의 정상적인 작업을 방해하는 신호
        - 인터럽트의 종류에는 예외와 하드웨어 인터럽트가 있다.
        - 인터럽트 서비스 루틴은 인터럽트를 처리하기 위한 동작들로 이루어진 프로그램!
        - 멀티패스 다운로드 검색해서 우분투 실습 가능.

### 📌 Charter 5. CPU 성능 향상 기법

- **클럭**
    - 컴퓨터 부품들은 ‘클럭 속도’에 맞춰 움직인다.
    - 클럭 속도가 높아지면 CPU는 명령어 사이클을 더 빠르게 반복한다.
    - 클럭 속도는 헤르츠(Hz) 단위로 측정. (1초에 클럭이 몇 번 반복되는지)
    - 그러나 클럭 속도만 늘린다고 CPU가 빨라지지는 않는다. 무작정 높이면 발열 문제 심각. ——> 해결법은 코어 수를 늘리거나 스레드 수를 늘리는 방안이 있다.
- **코어와 멀티코어**
    - 코어? CPU : 명령어를 실행하는 부품을 여러 개 포함하는 부품 으로 오늘날 코어로 불린다.
    - 멀티코어: 듀얼→트리플→쿼드→헥사→옥타→데카→도데카…. 굳이 외울 필요는…없다..
- **스레드와 멀티스레드**
    - 스레드
        - 하드웨어적 스레드: 하나의 코어가 동시에 처리하는 명령어의 단위 (*하이퍼스레딩 : 인텔의 멀티스레드 기술.)
        - 소프트웨어적 스레드 ? 실행 흐름의 단위! 하나의 프로그램에서 독립적으로 실행되는 단위
    - 멀티스레드 프로세서
        - 멀티코어 프로세서 ： 명령어를 실행할 수 있는 하드웨어 부품이 CPU안에 두 개 이상 있는 CPU
        - 멀티스레드 프로세서 ： 하나의 코어로 여러개의 명령어를 동시에 실행할 수 있는 CPU
- **확인문제**
    - 클럭 신호는 CPU의 속도 단위 입니다.
    - 스레드는 코어가 처리할 수 있는 작업 단위입니다.
- **명령어 파이프라인**
    - 명령어 처리 과정을 클럭 단위로 나누어 보면 아래와 같이 나눌 수 있다.
        1. 명령어 인출(Instruction Fetch)
        2. 명령어 해석(Instruction Decode)
        3. 명령어 실행(Execute Instruction)
        4. 결과 저장(Write Back)
    - 같은 단계가 겹치지만 않는 다면 CPU는 ‘각 단계를 동시에 실행할 수 있다’
    - 파이프라인 위험에는 3가지 위험이 있다.
        - 데이터 위험: 이전 명령어의 데이터에 의존하는 경우
        - 제어 위험: 기본적으로 PC는 ‘현재 실행중인 명령어의 다음 주소’로 갱신되나 분기 등으로 ‘PC의 갑작스러운 변화로 실행 흐름이 변경되는 경우
        - 구조적 위험(=자원 위험): 서로 다른 명령어가 동시에 ALU, 레지스터 등과 같은 CPU 부품을 사용하려고 하는 경우
- **슈퍼스칼라**
    - 여러 개의 명령어 파이프라인을 포함한 구조
- **비순차적 명령어 처리(OoOE)**
    - 명령어의 합법적인 새치기
    - 명령어들 중에 서로 데이터 의존성이 없는 명령어를 미리 처리함.(의존성 있는 경우 기다려야 하므로)
- **명령어 집합**
    - 명령어 집합 또는 명령어 집합 구조(ISA, Instruction Set Architecture)가 다르면 CPU가 이해할 수 있는 명령어가 다르다는 뜻이고, 명령어가 달라지면 어셈블리어도 달라진다.
    - ISA가 같은 CPU끼리는 서로의 명령어를 이해할 수 있지만, ISA가 다르면 서로의 명령어를 이해하지 못한다.
    - 명령어 병렬 처리 기법들을 도입하기 유리한 ISA의 양대산맥 CISC vs RISC
        - CISC(Complex Instruction Set Computer)
            - 복잡하고 다양한 수의 가변 길이 명령어를 활용
            - 상대적으로 적은 수의 명령어로 프로그램 실행
            - 명령어의 크기와 실행되기까지의 시간이 일정하지 않음.
            - 명령어를 실행하는 데에 여러 클럭 주기를 필요로 함.
            - 다양한 주소 지정 방식
        - RISC(Reduced Instrction Set Computer)
            - 단순하고 적은 수의 고정 길이 명령어를 활용
            - 상대적으로 많은 명령어의 수
            - 1클럭 내외로 명령어를 수행하여 파이프라이닝에 최적화
            - CISC보다 적은 주소 지정 방식

## <a id="day-3-메모리와-캐시-메모리--보조기억장치"></a> Day 3

### 📌 Charter 6. 메모리와 캐시 메모리

- **RAM의 특징과 종류**
    - 특징: 휘발성 저장 장치
    - 종류
        - DRAM(Dynamic RAM): 저장된 데이터가 동적으로 사라짐, 일정 주기로 재활성화 필요, but 소비 전력이 낮고 저렴, 집적도가 높아 대용량 설계 용이 (주기억장치(RAM)에 주로 사용)
        - SRAM(Static RAM): 저장된 데이터가 정적인(사라지지 않는) RAM, DRAM보다 빠름 (캐시 메모리에 사용)
        - SDRAM(Synchronous Dynamic RAM): 클럭과 동기화된 DRAM = 클럭 타이밍에 맞춰 CPU와 정보를 주고 받을 수 있다.
        - DDR SDRAM(Double Data Rate SDRAM): 대역 폭을 넓혀 속도를 빠르게 만든 SDRAM, 가장 흔히 사용됨. 대역폭은 데이터를 주고 받는 길의 너비
    - 확인문제
        - RAM은 휘발성 저장 장치, 보조기억장치는 비휘발성 저장 장치
        - DRAM은 시간이 지나면 저장된 데이터가 점차 사리지며, SRAM은 시간이 지나도 사라지지 않는다.
        - SDRAM은 클럭과 동기화된 DRAM
        - DDR SDRAM은 SDR SDRAM에 비해 대역폭이 두 배 넓다.
- **메모리의 주소 공간**
    - 물리 주소와 논리 주소
        - 물리 주소는 메모리 하드웨어 상의 주소이고, 논리 주소는 CPU와 실행 중인 프로그램이 사용하는 주소이다.
        - 논리 주소와 물리 주소 간의 변환은 CPU와 주소 버스 사이에 위치한 메모리 관리 장치(MMU, Memory Management Unit)라는 하드웨어에 의해 수행
    - 메모리 보호 기법
        - 다른 프로그램의 영역을 침법할 수 있는 명령어를 방지하고 실행 중인 프로그램이 다른 프로그램에 영향을 받지 않도록 보호하기 위해 한계 레지스터가 나타남.
        - 베이스 레지스터 값 ≤ 프로그램의 물리 주소 범위 ≤ 베이스 레지스터 값+한계 레지스터 값
    - 확인 문제
        - 물리 주소는 메모리 하드웨어상의 주소, 논리 주소는 CPU와 실행 중인 프로그램이 사용하는 주소
        - MMU는 논리 주소를 물리 주소로 변환함.
        - 베이스 레지스터는 프로그램의 첫 물리 주소를 저장
        - 한계 레지스터는 실행 중인 프로그램의 논리 주소의 최대 크기를 저장.
- **캐시 메모리**
    - 저장 장치 계층 구조
        - CPU와 가까운 저장 장치는 빠르다. (1. 캐시메모리 2. 메모리 3. 보조기억장치 순으로 속도가 빠르며, 용량이 작고, 가격은 비싸다.)
    - 캐시 메모리
        - CPU가 메모리에 접근하는 속도는 레지스터에 접근하는 속도보다 느림. 그래서 캐시 메모리가 등장!
        - CPU와 메모리 사이에 위치하고, 레지스터보다 용량이 크고 메모리보다 빠른 SRAM 기반의 저장 장치
        - 계층: 코어(CPU)와 가까움 - L1 - L2 - L3
        - 캐시 적중률을 높여야 함: 참조 지역성의 원리에 의해 CPU가 사용할 법한 데이터를 예측.
            - 시간 지역성 : 최근에 접근했던 메모리 공간에 다시 접근
            - 공간 지역성 : 접근한 메모리 공간 근처를 접근
    - 확인 문제: 캐시 적중률이 높으면 CPU의 메모리 접근 횟수를 줄일 수 있다.

### 📌 Charter 7. 보조기억장치

- **다양한 보조기억장치**
    - 하드 디스크
        - 자기적인 방식으로 데이터 저장
        - 구성: 플래터(트랙과 섹터 단위로 데이터 저장), 스핀들, 헤드, 디스크 암
        - 데이터 접근 과정: 탐색 시간(헤드 이동 시간), 회전 지연(플래터 회전 시간), 전송 시간(데이터 전송 시간)
    - 플래시 메모리
        - 전기적으로 데이터를 읽고 쓸 수 있는 반도체 기반의 저장 장치
        - 셀(Cell) : 플래시 메모리에서 데이터를 저장하는 가장 작은 단위
        - 종류 (하나의 셀에 몇 비트를 저장할 수 있느냐에 따라 나눔!!): 
            - SLC : 한 셀에 1비트 저장, 수명 김, 가격 높음, 고성능 장치 사용
            - MLC : 2비트 저장, SLC보다 대용화 유리, 가격 저렴
            - TLC : 3비트 저장
        - 저장 단위: Page - Block - Plane - Die (읽기와 쓰기는 Page 단위, 삭제는 Block 단위)
        - 상태: Free(데이터 X), Valid(데이터 O), Invalid(쓰레기값, 유효하지 않은 데이터 상태)
        - SSD를 비롯한 플래시 메모리는 이러한 값을 정리하기 위해 가비지 컬렉션 기능을 제공
    - 확인 문제
        - 하드 디스크에서 데이터는 플래터에 저장
        - 플래터를 돌리는 구성 요소는? 스핀들
        - 하드 디스크에 저장된 데이터를 읽고 쓰는 구성 요소? 헤드
- **RAID의 정의와 종류**
    - RAID는 주로 하드 디스크와 SSD를 사용하는 기술로 데이터의 안전성 혹은 높은 성능을 위해 여러 개의 물리적 보조기억장치를 하나로 사용하는 기술
    - 종류
        - RAID 0: 스트라이핑(분산하여 저장)
        - RAID 1: 미러링(복사본 만드는 방식, 느린 쓰기 속도)
        - RAID 4: 패리티 비트 저장
        - RAID 5: 패리티 정보를 분산하여 저장
        - RAID 6: 두 종류의 패리티를 두는 방식, RAID 5보다 안전하지만 쓰기는 더 느림
    - 확인 문제
        - RAID란 데이터의 안전성 혹은 높은 성능을 위해 여러 하드 디스크나 SSD를 마치 하나의 장치처럼 사용하는 기술
        - RAID 0는 데이터를 단순히 병렬로 분산하여 저장하고, RAID 1은 완전한 복사본을 만든다.
        - RAID 4는 패리티를 저장한 장치를 따로 두는 방식이고, RAID 5는 패리티를 분산하여 저장하는 방식
        - RAID 6는 서로 다른 두 개의 패리티를 두는 방식
     
### 📌 Charter 8. 입출력장치

- **장치 컨트롤러**
    - 필요한 이유? 입출력장치의 종류가 너무 다양해 규격화 하기 어려움 / CPU와 메모리에 비해 입출력장치 전송률이 낮음
    - 역할: 통신 중개, 오류 검출, 데이터 버퍼링
    - 내부 구조: 데이터 레지스터, 상태 레지스터, 제어 레지스터
- **장치 드라이버**: 장치 컨트롤러의 동작을 감지하고 제어하는 프로그램
- **확인 문제**
    - 입출력장치는 장치 컨트롤러를 통해 컴퓨터 내부와 정보를 주고 받는다.
    - 장치 드라이버는 장치 컨트롤러가 컴퓨터 내부와 정보를 주고 받을 수 있게 하는 프로그램.
    - 컴퓨터가 장치 드라이버를 인식하고 실행할 수 있다면 해당 입출력장치의 사용이 가능.
- **프로그램 입출력**: 프로그램 속 명령어로 제어하는 방법 (메모리 맵 입출력 / 고립형 입출력)
- **인터럽트 기반 입출력**: 우선순위를 반영하기 위해 PIC(프로그래머블 인터럽트 컨트롤러) 하드웨어 사용
- **DMA 입출력**: CPU를 거치지 않고 직접 메모리에 접근하는 기능 (시스템 버스 부하를 줄이기 위해 별도의 입출력 버스 사용)
- **확인 문제**
    - 입출력 버스는 입출력 작업 과정에서 시스템 버스 사용 횟수를 줄여준다.
    - DMA 컨트롤러와 CPU는 시스템 버스를 동시에 사용할 수 없다.
    - DMA 컨트롤러는 CPU를 거치지 않고 메모리와 입출력장치 간의 데이터를 주고 받는다.

### 📌 Charter 9. 운영체제 시작하기

- **운영체제란**: 자원을 할당하고 프로그램이 실행되도록 돕는 특별한 프로그램. 메모리 내 커널 영역에 적재됨.
- **운영체제의 심장, 커널**: 운영체제의 핵심 서비스를 담당하는 부분
- **이중 모드와 시스템 호출**
    - 이중 모드: 커널 모드와 사용자 모드로 구분하는 방식 (사용자 모드는 자원 접근 불가)
    - 시스템 호출: 커널 서비스를 제공받기 위한 요청 (소프트웨어 인터럽트)
- **운영체제의 핵심 서비스**: 프로세스 관리, 자원 접근 및 할당
- **확인 문제**
    - 시스템 호출은 운영체제의 서비스를 제공받기 위해 커널 모드로 전환하는 방법.
    - 대표적인 운영체제 서비스로 프로세스 관리, 자원 접근 및 할당, 파일 시스템 관리가 있다.

### 📌 Charter 10. 프로세스와 스레드
#### 1. 프로세스 개요
- **프로세스 확인**: 포그라운드 프로세스 / 백그라운드 프로세스
- **프로세스 제어 블록 (PCB)**: 프로세스 순서 관리 및 자원 배분을 위해 이용 (PID, 레지스터 값, 프로세스 상태, 스케줄링 정보, 메모리 관리 정보 등 포함)
- **문맥 교환**: 기존 프로세스 문맥을 PCB에 백업하고 새로운 프로세스 문맥을 복구하는 것
- **프로세스의 메모리 영역**
    - 정적 할당 영역: 코드 영역(기계어 명령어), 데이터 영역(전역 변수)
    - 동적 할당 영역: 힙 영역(프로그래머 할당 공간, 낮은->높은 주소), 스택 영역(일시적 저장 공간, 높은->낮은 주소)
- **데이터, 힙, 스택 영역의 차이?!**
    - **데이터 영역**: 전역 변수/정적 변수 저장, 시스템이 자동 관리
    - **힙 영역**: 사용자가 직접 할당/해제하는 데이터, 프로그래머가 관리
    - **스택 영역**: 지역 변수/매개변수/리턴 주소 등, 시스템이 자동 관리
- **할당 방향이 다른 이유**: 한정된 메모리 공간을 최대한 효율적이고 유연하게 사용하기 위해 서로 마주 보는 구조로 설계하여 충돌 방지 및 관리 용이성 확보

## <a id="day-4-프로세스와-스레드--CPU-스케줄링--프로세스-동기화-"></a> Day 4

### 📌 Charter 10. 프로세스와 스레드
#### 2. 프로세스 상태와 계층 구조
- **프로세스 상태**
    - **생성 상태(New)**
    - **준비 상태(Ready)**
        - 준비→실행 전환되는 것을 Dispatch(디스패치)라고 한다.
    - **실행 상태(Running)**
        - 할당된 시간을 모두 사용하면 준비 상태로 변환
    - **대기 상태(Blocked)**
        - 입출력 장치의 작업을 기다리는 상태
        - 입출력 작업이 완료되면 해당 프로세스는 다시 준비 상태로 변환
    - **종료 상태(Terminated)**
- **프로세스 계층 구조**
    - 트리 구조로 되어 있으며 부모 프로세스, 자식 프로세스로 구성됨.
    - 각기 다른 PID를 가지고 있으며, 자식 프로세스의 PCB에 부모 프로세스PID인 PPID가 기록된다.
    - 리눅스에서 pstree 로 최초 프로세스 확인 가능.
- **프로세스 생성 기법**
    - fork 시스템 호출
        - 복사본(=자식 프로세스) 생성
        - 부모 프로세스의 자원(메모리 내의 내용, 열린 파일의 목록 등) 상속
    - exec 시스템 호출
        - 메모리 공간을 새로운 프로그램으로 덮어쓰기
        - 코드/데이터 영역은 실행할 프로그램 내용으로 바뀌고 나머지 영역은 초기화
- **확인 문제**
    - fork 시스템 호출은 폴더 생성과 관련이 없다.
    - exec 시스템 호출을 하면 프로세스의 메모리 공간이 다른 프로세스의 내용으로 변경된다.
- **스레드**
    - **프로세스와 스레드**
        - 스레드란? 프로세스를 구성하는 실행 흐름의 단위
    - **멀티 프로세스와 멀티 스레드**
        - 멀티 프로세스 : 여러 프로세스를 동시에 실행
        - 멀티 스레드 : 여러 스레드로 프로세스를 동시에 실행
        - 프로세스를 fork하면 코드/데이터/힙 영역 등 모든 자원이 복제되어 저장됨
        - 저장된 메모리 주소를 제외하면 모든 것이 동일한 프로세스 두 개가 통째로 메모리에 적재
        - fork를 세 번 ,네 번하면 메모리에는 같은 프로세스가 통째로 세 개 ,네 개 적재
- **확인 문제**
    - 프로세스 내의 스레드들은 각기 다른 코드/데이터/힙 영역을 가지고 있지 않습니다.
    - 프로세스끼리는 기본적으로 자원을 공유하지 않지만, 프로세스 내의 스레드끼리는 같은 프로세스 내의 자원을 공유합니다.

### Charter 11. CPU 스케줄링
- **프로세스 우선순위**
    - **가장 공정한 CPU 스케줄링이란?**
        - 입출력 작업이 많은 프로세스(=입출력 집중 프로세스)의 우선순위는 CPU 작업이 많은 프로세스(=CPU 집중 프로세스) 의 우선순위보다 높다.
    - **스케줄링 큐**
        - 큐는 자료 구조 관점에서 선입선출 구조이지만, 스케줄링에서는 반드시 선입선출일 필요는 없다.
        - 준비 큐 : CPU를 이용하고 싶은 프로세스들이 서는 줄
        - 대기 큐 : 입출력장치를 이용하기 위해 대기 상태에 접어든 프로세스들이 서는 줄
    - **선점형과 비선점형 스케줄링**
        - 선점형 스케줄링 : 하나의 프로세스가 자원 사용을 독점할 수 없음.
        - 비선점형 스케줄링 : 하나의 프로세스가 자원 사용을 독점할 수 있는 스케줄링 방식.
- **확인 문제**
    - 선점형 스케줄링은 문맥 교환 과정의 오버헤드가 비선점형 스케줄링에 비해 크다!!
- **CPU 스케줄링 알고리즘**
    - * 적은 시간이지만 순위가 밀려 긴 시간을 기다리는 현상을 **호위 효과(convoy effect)**라고 한다.
    1. **선입 선처리 스케줄링**(**FCFS**) - 비선점  
    2. **최단 작업 우선 스케줄링**(**SJF**)  
    3. **라운드 로빈 스케줄링**(**RR**)  
        1. 타임 슬라이스란 각 프로세스가 CPU를 사용할 수 있는 정해진 시간이 있으며 해당 시간이 만료되면 문맥 교환이 이루어진다.  
    4. **최소 잔여 시간 우선 스케줄링**(**SRT = RR + SJF**)  
        1. 작업시간이 짧은 프로세스부터 처리하는데, 타임 슬라이스만큼 돌아가며 CPU를 사용하는 선점형 스케줄링 알고리즘.  
    5. **우선순위 스케줄링**  
        1. 우선순위가 같은  프로세스들은 선입 선처리로 스케줄링 된다.  
        2. SJF, SRT 가 넓은 의미에서 우선순위 스케줄링에 포함된다.  
        3. 우선순위가 낮을 경우 계속해서 연기되며 기아 현상이 발생할 수 있다. → 이를 방지하기 위한 에이징 기법이 있다. (에이징 : 오랫동안 대기한 프로세스의 우선순위를 점차 높여줌)  
    6. **다단계 큐 스케줄링**  
        1. 우선순위별 준비 큐를 여러 개 사용하는 스케줄링 방식  
        2. 프로세스들이 서로 다른 큐를 이동할 수 없다.  
    7. **다단계 피드백 큐 스케줄링**  
        1. 다단계 큐 스케줄링의 단점을 보완하여 서로 다른 큐를 프로세스가 이동할 수 있다.  

### Charter 12. 프로세스 동기화

- **동기화의 의미**
    - 프로세스들의 수행 시기를 맞추는 것
    - 실행 순서 제어 동기화 : 프로세스를 올바른 순서대로 실행하는 실행 순서 제어를 위한 동기화
    - 상호 배제 동기화 :  동시에 접근해서는 안 되는 자원에 하나의 프로세스만 접근하게 하는 동기화
- **공유 자원과 임계 구역**
    - **공유 자원** : 동시에 접근할 수 있는 자원으로 전역 변수, 파일 등이 될 수 있다.
    - **임계 구역** : 동시에 실행하면 문제가 발생하는 자원에 접근하는 코드 영역
    - **레이스 컨디션** : 여러 프로세스가 동시 다발적으로 임계 구역의 코드를 실행하여 문제가 발생.
    - **상호 배제** : 한 프로세스가 임계 구역에 진입했다면 다른 프로세스는 임계 구역에 들어올 수 X
    - **진행** : 임계구역에 아무도 진입하지 않았다면 진입 가능
    - **유한 대기** : 임계 구역에 들어오기 위해 무한정 대기 X
